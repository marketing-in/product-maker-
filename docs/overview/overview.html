Overview · how the application works

Teardown Lab

Say what you want to build, show a product you have, or upload a circuit board. An agent takes it from idea to the files to make it.

Design something new

One sentence becomes a plan, a 3D design with a board and housing, firmware and a parts list.

Take apart a product you have

Photos or a description become a part-by-part teardown with the wiring and the power on every path.

Make a housing for your board

A Gerber set or a KiCad file becomes a moulded enclosure designed round the board.

Built on Claude, three.js, KiCad and Kitspace formats, rea and Blender.

Change it, then operate it

Move parts by hand, then press the product’s buttons

Design editor

  • Drag a part in 3D or type its position and size; a board moves with everything on it.
  • Resize the housing and change its wall; the fit check updates as you go.
  • Undo and reset; every view and export follows the change.

Simulator

  • Wheeled products drive across a floor with the arrow keys; fans spin; a camera shows a live picture.
  • Speakers and sound machines play: music, white noise, rain, ocean, with a level meter.

Teardown Lab · overview6
Housing and firmware

Does it fit, how is it moulded, and what runs on it

Fit and mould

  • Parts coloured by fit: fits, tight, needs a cut-out, crosses the wall, overlaps.
  • Open the mould slides each housing part along the direction its tool opens.
  • Per part: material, wall, draft, ribs, shrink, mass, clamp force, cooling time; sheet and wood parts get sheet advice.

Firmware

  • Written for the controller actually in the design, with a pin map that matches the board.
  • Upload existing firmware and rea inspects it on your computer.

Trust

Honest about what it knows, tested on every screen

Every part says how sure it is

With the evidence behind it and the open question to close. Estimates are never shown as measurements.

Checks after every change

Electrical rules, connections, fit in the housing, clashes, temperature, battery, board layout and controls, each with a link to where to look.

Limits it states plainly

  • Sizes, part numbers and values are estimates until measured.
  • Board copper is an autorouted first pass; review it in KiCad.
  • Firmware is written from the design and not compiled here.

npm run test:ui drives the real app in a headless browser: the sample and every saved project on every tab, the editor, the simulator, every download, and laptop, tablet and phone widths. It fails on page errors, failed API calls, sideways scrolling, text spilling out of buttons, unreadable code and pages that open in the wrong place.

Found and fixed by it

  • Phones opened scrolled to the bottom of the page.
  • Wood and metal parts got plastic-moulding advice.
  • Opening a saved project re-saved it.
  • Firmware code was unreadable on its dark background.

Getting started

Run it on your computer, or online

On your computer

npm install
cp .env.example .env     # add ANTHROPIC_API_KEY
npm run dev              # http://localhost:5173
npm run setup:rea        # optional: firmware inspection
npm run test:ui          # full interface test
npm run push             # save generations and push

Without a key the built-in sample still works on every screen.

Online with Vercel

The same repository deploys as is. Set ANTHROPIC_API_KEY and APP_PASSWORD (and ANTHROPIC_WORKSPACE_ID for a user-scoped key). Without an access code the agent stays off, so a public address cannot spend your credit. Projects are kept in each visitor’s browser.
